# 更正记录 · `enforced` 字段缺失导致的误拦截率错误

> 触发：用新执行器重跑 M1 travel 后，同一权重两次运行的**场景级结果 60/60 完全一致**，
> 但"干净场景误拦截"从 **0/97** 变成 **11/97**。追查发现是字段缺失，不是行为差异。

## 1. 问题

`ad_run3.py` 在引入 `--review-policy` 时才把 `enforced` 写进 `guard_hits`。
**在此之前产生的运行没有这个字段**。我早期用它算误拦截率时写的是 `h.get('enforced')`，
缺字段时返回 `None` → 全部被当成"未执行"，于是**误拦截率恒为 0**。

## 2. 影响范围（已逐个核查 14 个运行）

| 运行 | guard_hits | 含 enforced | 是否受影响 |
|---|---|---|---|
| `travel/m2_HB_s0_inj0-1`（旧 M1） | 321 | **0** | **是（唯一一个）** |
| `travel/m2_HB_s0_inj0-1_revallow` | 304 | 304 | 否 |
| `travel/m2_HBnt_s0_inj0-1`（M0） | 305 | 305 | 否 |
| `travel/{pg2,rule-gamma}_inj0-1` | 294 / 310 | 全部 | 否 |
| `slack/m2_HB_s0_inj1-3` 等 4 个 | 331–414 | 全部 | 否 |
| `banking/{none,m2_HBnt_s0,m2_HB_s0}_inj5-7` | 0/102/103 | 全部 | 否 |

**只有一次运行受影响**，而它正是 travel 上 M1 的旧记录。其余 13 个运行的 `enforced` 完整。

## 3. 修正规则

```python
def enf(h):
    if 'enforced' in h: return bool(h['enforced'])
    return h.get('decision') != 'ALLOW'   # 当时策略固定为 block
```

并且 travel 的 M1 一律改用**新跑**（`results/e2e/travel/m2_HB_s0_calls_inj0-1`，含 calls）。
旧运行保留在盘上，不删除。

## 4. 被更正的数字

| 位置 | 原写法 | 更正后 |
|---|---|---|
| `phase1_baseline_v2.md` §1.3② M1 travel 干净误拦截 | 0/97（0.0%） | **11/97（11.3%）**，且 11 次**全部是 REVIEW**、无 DENY |
| `phase1_travel_m0.md` §2 同格 | 0/97（0.0%） | 同上 |
| 结论"任务感知零误拦截代价" | 不成立 | **在 block 策略下 M1 的调用级误拦截高于 M0**（11.3% vs 3.3%），换成 allow 策略才是 0 |

## 5. 修正后 travel 的完整对照

| 臂 | REVIEW 策略 | ASR | 干净完成 | 干净误拦截（调用级） | 攻击场景内合法调用误拦 |
|---|---|---|---|---|---|
| E0 无守卫 | — | 13/40（32.5%） | 5/20（25.0%） | — | — |
| **M0 任务盲** | block | 6/40（15.0%） | 2/20（10.0%） | 3/92（3.3%）〔2 DENY + 1 REVIEW〕 | 3/197（1.5%） |
| **M1 任务感知** | block | **1/40（2.5%）** | 2/20（10.0%） | **11/97（11.3%）〔全 REVIEW，0 DENY〕** | 34/214（15.9%） |
| **M1 任务感知** | **allow** | **1/40（2.5%）** | **3/20（15.0%）** | **0/93（0.0%）** | — |

**结论因此改变**：不是"M1 零误拦截"，而是**"M1 的干净侧代价全部来自 REVIEW 处置策略"**。
在推荐策略（REVIEW=放行+记日志）下，M1 在两个轴上都优于 M0：
ASR 15%→2.5%，干净效用 10%→15%，误拦截 3.3%→0。

这一条与早期 REVIEW 消融（"REVIEW 当阻断买不到安全只买成本"）方向一致，
但当时只有场景级证据，现在是调用级。

## 6. 仍然存在的问题

1. **攻击场景内合法调用误拦率 15.9%（M1）远高于离线 `CCB_inj` 0.036**。原因是线上轨迹在拦截后会分叉，
   产生离线从未见过的调用（多为重试/改参），这些调用被计入"合法"。该指标在线上是**上界**，
   不能与离线的 `CCB_inj` 直接比。
2. **M0 的"攻击内合法误拦 1.5%"也受同一机制影响**，只是 M0 拦得少、分叉少，膨胀不明显。
3. 旧运行（无 calls）**无法补算**调用级指标，只能保留场景级。已在新报告里标注 n/a。
