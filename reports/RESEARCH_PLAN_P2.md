# P2 研究主线：轻量级 Task-Aware 运行时安全控制

> 起点：P1/M2 已冻结（`frozen/FREEZE_P1M2.md`，2026-11-01 18:57）。
> 本文件是**新主线**的定位、证据地图与补实验清单，不是对旧结论的追认。

---

## 0. 一句话主张

**一个 1.5B 的判别器，只要在"被污染的上下文里"见过同一动作的合法对照，就能学会用任务意图判断
工具调用是否越权；它能在 254 ms/次的开销下把 Agent 的攻击成功率压到 0，同时不牺牲干净任务。**

三个要素缺一不可：**任务意图（输入）→ 配对数据配方（训练）→ 执行边界（部署）**。
论文的价值不在"提出任务对齐"这个概念（已有工作做过），而在**证明它需要什么条件才成立，以及不成立时
离线指标会怎样骗人**。

## 2. 定位：与最近邻工作的差异

| | Task Shield (ACL 2025) | ToolSafe (2026) | Prompt-Guard-86M | **本文** |
|---|---|---|---|---|
| 判据 | 让 LLM 检查"这个调用是否服务于用户目标" | 逐步检测 + 安全反馈 | 文本可疑度 | 1.5B LoRA 读结构化三元组（请求 / 历史 / 当前动作） |
| 用不用任务 | 用（塞进 prompt） | 部分 | 不用 | 用（独立字段，非自然语言拼接） |
| 单次成本 | 一次 LLM 调用（秒级） | 一次模型调用 | 86M 分类器（30 ms） | **254 ms** |
| 评测方式 | ASR + utility | ASR + utility | 分类指标 | **诊断协议 + 因果量 dInj + 在线 ASR/utility** |
| 主要贡献 | 方法 | 方法 + 反馈 | 模型 | **测量协议 + 数据配方 + 轻量部署经济学** |

**不要声称"我们提出任务感知"**。要声称的是三条可验证的、别人没做过的：

1. **测量**：离线对齐指标与在线拦截率**方向可以相反**（1.5B：PRA 0.841 → ACB 0.331；
   3B：0.885 → 0.170）。并给出能识破退化的指标 `CCB_inj`（受攻击场景里合法调用的误拦率）。
2. **配方**：让 1.5B 真的用任务意图的，不是加负例，而是**在同一条被污染的上下文里给出合法对照**。
   同量同比例同工具分布，只把正例挪出污染上下文，模型立刻退化成"看到 `<INFORMATION>` 就拦"
   （`CCB_inj` 0.036 → 0.439）。
3. **部署**：在这个成本档位上（254 ms）拿到 0% ASR 且零干净任务损失（slack），
   而 86M 分类器要 5.5 倍拦截量才压到 14.3%。

第 3 条要成立，必须补上 §3 的 E6，否则"轻量"只是参数量叙事。

## 4. 必须补的实验（按 ROI 排序）

### E1 · 任务字段消融（推理时抹掉请求）— ✅ 已完成 2026-11-01 19:30
**结果**：HB ACB 0.918→0.893（−2.5pp，噪声内），但**干净零打扰 0.905→0.619（−28.6pp）**、
CCB_clean 0.007→0.045。S 掉得更狠（ACB −16.4pp），H 的零打扰直接归零。
**结论**：任务字段的价值在效用侧，聚合 ACB 看不见。详见 `P2_ablation.md`。

**问题**：同一个 HB 权重，把 prompt 里的用户请求抹掉，ACB/CCB 会怎样？
**做法**：`diag_score.py --no-task`（已支持，标签自动加 `_notask`），跑 HB / S / H 三臂。
**成本**：~20 分钟 GPU，无训练。
**产物**：`m2_HB_s0_notask` 等三臂进 `metrics.json`，与带任务版逐格对比。
**如果差异很小**：说明 HB 靠的是"历史里的对照"而不是任务字段，论文叙事要改成"上下文配对"为主、
任务信息为辅——这本身也是可发表的结论，但方法定位要改。

### E2 · 任务盲训练臂（HB-nt）— ✅ 已完成 2026-11-01 19:50
**结果**：val macro-F1 0.9039→0.8554；**ACB 0.918→0.585（−33.3pp）**、干净零打扰 0.905→0.476；
dInj +0.233→+0.553，88 条因载荷改判 DENY、0 条被放行。ACB(`noinj`)=0.031 → 退化成载荷检测器。
**结论**：配对数据让模型变保守，只有任务字段能让保守落在正确位置。

**问题**：训练时就不给任务字段，只给历史 + 当前动作，数据配方完全相同。
**做法**：给 `train_drift.py` 加 `--no-task`（照 `p1_run.py` 的 `no_task` 渲染分支抄），
用 `hardneg_bal.jsonl` 训一个 `m2_HBnt_s0`，再评分。
**成本**：训练 15 分 + 评分 7 分。
**为什么必须做**：E1 只改推理分布（训练-推理不匹配），E2 才是干净的"任务信息贡献"对照。

### E3 · Task-Shield 式 LLM judge 基线（正面对比最近邻工作）
**问题**：用同一条 7B 模型做"这个调用是否服务于用户目标"的逐步判定，在同一协议下打多少？
**做法**：实现 `TaskShieldGuard`，复用现有 `decide(instruction, history, current_action)` 接口，
prompt 按论文描述写（给定用户目标 + 当前调用，输出 YES/NO）；先离线跑 300 条子集校准阈值，
再跑一条 slack 端到端。
**成本**：离线 8 分 + 端到端 1 小时（每次判定 ~1.5 s，实际调用 400 次 ≈ 10 分钟判定 + agent 生成）。
**产物**：ASR / Utility / 单次延迟三联对比，这是"我们比 Task Shield 强在哪"的唯一硬证据。
**风险**：它可能也很强但慢 6 倍——那结论就要改成"同等安全、成本低一个量级"，依然是正面结果。

### E4 · banking 端到端
**问题**：动机例子（转账 100 元 vs 被网页诱导转 1000 元）所在的套件，线上成立吗？
**做法**：先跑无守卫基线（1 小时），再跑 HB（1 小时），`e2e_analyze.py` 出全套指标。
**成本**：~2 小时。
**注意**：banking 在 hardneg 训练集里出现过，所以这条只能作为 **in-distribution** 证据，
泛化仍由 travel 承担。

### E5 · 跨 agent（换 scaffold）
**问题**：结论是不是只对 AgentDojo 原生 pipeline 成立？
**做法**：接一个不同 scaffold（如 ReAct 手写循环或 LangChain agent），跑 travel 的子集（10 任务 × 2 注入）。
**成本**：实现 2 小时 + 跑 1.5 小时。
**为什么排后面**：贵且容易引入新变量；但审稿人一定会问"是不是 pipeline 特异"。

### E6 · 效率的系统测量
**问题**："轻量"到底轻在哪，代价是几倍？
**做法**：已有 trace 里的 254/30/0 ms；补三件事——(a) 批量吞吐（bs=1/8/32 的 calls/s），
(b) 显存占用，(c) 与 7B judge 的单次延迟对比（E3 顺带产出）。
**成本**：~30 分钟。
**产物**：一张"成本 × 安全 × 效用"的三维表，这是本文相对 Task Shield 的核心卖点。

## 5. 论文结构（每节必须证明什么）

| 节 | 内容 | 必须证明 | 数据来源 |
|---|---|---|---|
| 1 动机 | Agent 的工具调用会偏离用户任务 | 现有判据（工具敏感度、文本可疑度）会同时漏检与误杀 | `baselines_controls.md` §2 |
| 2 问题分析 | "动作危险"与"动作越权"不是一回事 | 同一批调用，删掉攻击者那句话，拦截率 0.33→0.71（dInj 三 seed 全负） | 表 B |
| 3 方法 | 1.5B 判别器 + PAB 三元组 + 配对数据配方 | 任务字段与配对上下文各自贡献可分离 | **E1/E2** + HB-sm |
| 4 集成 | 执行边界上的三档决策（ALLOW/REVIEW/DENY） | REVIEW 当阻断不买安全只买成本 | `e2e_ablation.md` §1 |
| 5 端到端 | 四臂 × 两套件 | ASR 降、效用保、而且是"部分拦截打断链" | `e2e_ablation.md` |
| 6 对比 | 规则 / PG2 / Task-Shield 式 judge | 同等安全下成本低一个量级，或同等成本下更安全 | **E3/E6** |
| 7 局限 | 读类攻击、单 scaffold、seed 敏感性 | 如实标注 | `FREEZE_P1M2.md` §5 |

**已有 5 节的数据是齐的，缺的是第 3 节的消融和第 6 节的对比。**

## 6. 不能声称的事（写进 Limitations）

1. **不能说"任务感知是我们提出的"**——Task Shield / ToolSafe 已做过，我们做的是条件、配方与成本。
2. **不能说"泛化到任意 agent"**——只有 AgentDojo 原生 pipeline（E5 补之前）。
3. **不能说"travel 上的 0.800"**——那是 seed 0；3 seed 均值 0.662±0.147。
4. **不能说"REVIEW 比 DENY 更安全"**——两者 ASR 相同（1/40）。
5. **不能说"离线指标能预测效用"**——`IntactW` 预测零打扰 0.762，线上只保住 40% 相对效用。
6. **不能说"读类攻击也能防"是靠工具规则**——规则对 `get_webpage` 类攻击 13/21 全放；
   我们靠的是授权判断，这条要单独举一段。
