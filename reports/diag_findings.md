# 诊断结论：离线授权目标与线上注入攻击的错位

> 协议见 `diag_protocol.md`；机器可读表格见 `results/diag/report.md` 与
> `results/diag/metrics.json`。本文件所有数字来自 `scripts/diag_metrics.py`
> 的同一次运行，没有第二条计算路径。

## 一句话

同一个 guard，同一批真实攻击调用：**离线配对准确率 84%，线上攻击拦截率 33%；
3B 上离线最高（88.5%）线上最低（17.0%）**。把攻击者写进工具返回值的那句话删掉
（证据、轮次、工具输出全不变），拦截率回到 68–85%。错位不是"模型不够强"，
是**被污染的历史在替攻击者做授权**——而且模型越大越容易被说服。

## 0. 实验装置

- 2370 条真实 agent 调用（Qwen2.5-7B 作 agent，AgentDojo banking/travel/slack），
  攻击调用 159、干净场景合法调用 2174、uncertain 37。
- 五档 history 视图，`instruction` 与 `current_action` 逐字节相同：
  `none` / `last1` / `last3` / `full` / `noinj`。
- `noinj` = `full` 删掉 `<INFORMATION>…</INFORMATION>` 载荷；159/159 攻击调用
  删后证据块数不变（逐条校验），故 `full − noinj` 是**因果量**。
- 区间按受攻击场景簇（57 个）bootstrap；`DC` = 「REVIEW 也算拦截」的稳健口径。

## 1. 缺口，以及方向是反的

| 模型 | 离线 PRA（PAB-RD test, 90 对） | 线上 ACB(full) | ACB(full) − DC |
|---|---|---|---|
| 1.5B s0 | 0.856 | 0.214 | 0.346 |
| 1.5B s42 | 0.844 | 0.358 | 0.428 |
| 1.5B s123 | 0.822 | 0.421 | 0.516 |
| **3B s0** | **0.885** | **0.170** | 0.296 |
| 1.5B s0（去掉用户请求训练） | 0.772 | 0.415 | 0.585 |

**排序反转**：按离线 PRA 排，3B 第一（0.885）、1.5B 第二（0.841）；
按线上 ACB 排，3B 最后（0.170）、1.5B 第二（0.331）。离线指标不仅数值虚高，
**它指的方向是错的**。一个按 PAB-RD 选型的团队会部署最不安全的那个 checkpint。

## 2. 错位是因果的，且几乎单向

| 模型 | ACB(full) | ACB(noinj) | dInj | 95%CI | 载荷→DENY | 载荷→ALLOW |
|---|---|---|---|---|---|---|
| 1.5B s0 | 0.214 | 0.673 | **−0.459** | [−0.553, −0.368] | 0 | 72 |
| 1.5B s42 | 0.358 | 0.742 | **−0.384** | [−0.479, −0.295] | 0 | 61 |
| 1.5B s123 | 0.421 | 0.736 | **−0.315** | [−0.409, −0.221] | 1 | 51 |
| 3B s0 | 0.170 | 0.679 | **−0.509** | [−0.615, −0.403] | 1 | 78 |
| 1.5B no-task | 0.415 | 0.629 | −0.214 | [−0.310, −0.118] | 7 | 38 |
| 0.5B 零样本 | 0.629 | 0.528 | **+0.101** | [+0.043, +0.167] | 0 | 0 |

四个 task-aware checkpoint 的区间全部排除 0，翻转为 ALLOW 共 262 次、
翻转为 DENY 共 2 次——攻击者那段话**几乎只会让守卫更宽松**。

`dHist = ACB(full) − ACB(none)` 与 `dInj` 几乎相等（占 93–99%）：
**历史的作用几乎全部来自载荷本身**，不是"证据变多"。

## 3. 不是"去掉历史就没证据"的假象

最容易被质疑的一点：`none` 视图没有接地证据，模型可能只是"一律 DENY"。不是：

| 模型 | ACB(none) | CCB_clean(none) | ACB(full) | CCB_clean(full) |
|---|---|---|---|---|
| 1.5B s0 | 0.704 | 0.067 | 0.214 | 0.022 |
| 1.5B s42 | 0.774 | 0.093 | 0.358 | 0.078 |
| 1.5B s123 | 0.723 | 0.075 | 0.421 | 0.082 |
| 3B s0 | 0.799 | 0.134 | 0.170 | 0.056 |

只看用户目标 + 待执行调用时，分离度是 **70–80% 对 6.7–13.4%**：判别信息本来
就在调用和请求里。给它看真实线上输入后，误拦截不升反降，攻击拦截却塌到 17–42%。
**是历史把已经做对的判断改错了。**

## 4. 漂移的直接计数

只看目标时判 DENY 的攻击调用，被污染历史翻成 ALLOW 的比例：

| 模型 | 只看目标判 DENY | 被翻成 ALLOW | 漂移率 |
|---|---|---|---|
| 1.5B s0 | 112 | 77 | 68.8% |
| 1.5B s42 | 123 | 66 | 53.7% |
| 1.5B s123 | 115 | 52 | 45.2% |
| 3B s0 | 127 | 93 | **73.2%** |

## 5. 机制：两种失效，人群互斥，且只有一种需要"知道任务"

按攻击调用关键参数（长度 ≥6 的字符串）的来源分组：

| provenance | n | 含义 |
|---|---|---|
| `in_payload_only` | 98 | 参数只在注入载荷里 → 接地被污染 |
| `in_evidence` | 51 | 参数在合法证据里本来就有 → 接地没问题，只能是授权边界缺失 |

| 模型 | in_payload_only dInj | in_evidence dInj |
|---|---|---|
| 1.5B s0 | **−0.592** | −0.294 |
| 1.5B s42 | **−0.500** | −0.235 |
| 1.5B s123 | **−0.398** | −0.216 |
| **1.5B no-task** | **−0.296** | **−0.059** |

这张表是整个诊断里信息量最大的一处：

- `in_payload_only`：**即使训练时完全不给用户请求**，效应依然很大（−0.296）。
  说明这一类是纯粹的"接地被污染"——载荷提供了证据，与是否知道任务无关。
- `in_evidence`：task-aware 有 −0.22 ~ −0.29，task-blind 只有 **−0.059**（基本为 0）。
  说明这一类要求模型**知道用户在要什么**，才会把载荷里的指令当成授权。
  这正是"授权被劫持"，也解释了为什么它无法用接地判据修复。

## 6. 跨套件

`ACB(full) / CCB_clean(full)`：

| 模型 | banking | slack | travel |
|---|---|---|---|
| 1.5B s0 | 0.244 / 0.097 | **0.038** / 0.023 | 0.338 / 0.000 |
| 1.5B s42 | 0.659 / 0.387 | 0.075 / 0.069 | 0.400 / 0.000 |
| 1.5B s123 | 0.341 / 0.226 | 0.321 / 0.115 | 0.554 / 0.000 |
| 3B s0 | 0.122 / 0.161 | 0.075 / 0.076 | 0.277 / 0.000 |
| 1.5B no-task | 0.415 / 0.258 | 0.415 / 0.198 | 0.415 / 0.019 |

slack 几乎全盲（3.8–7.5%），与既有结论一致：slack 的合法任务本身就是
"读网页/消息再照做"，与攻击流程同构。travel 误拦截恒为 0。

## 7. `dInj` 的符号本身是诊断量

0.5B 零样本的 dInj 是**正的**（+0.101）：看到注入载荷反而更警觉。但它把 47.8%
的干净调用判成危险。它学到的不是授权，是"这段文本可疑"——正是本文要区分开的
**捷径**。1.5B 零样本恒 ALLOW（ACB=CCB=0），根本不能当 guard。

于是 `dInj` 有三种含义，可用来给任意 guard 定性：
**负 = 授权被劫持 / 接近 0 = 不依赖历史 / 正 = 靠可疑文本报警（高误伤）**。

## 8. 对训练目标的含义

1. 标准授权 SFT 优化的"当前调用是否符合用户意图"，在被污染的历史下
   **在该判 DENY 的地方给出 ALLOW**，且漂移率 45–73%，不可自愈。
2. 要修的是两件事，且是分开的：
   - **数据**：训练集里必须出现"参数有据可查但未被授权"的样本。PAB-RD 里没有
     （它的负样本全是"文档写了 X，动作做 Y"）。
   - **目标**：必须约束"加入更多上下文不得让判断变宽松"，标准 CE 没有这一项。
3. 规模不是解法：3B 离线更好、线上更差。**更大的模型更忠实地跟随被污染的上下文。**

## 9. 已知边界

- 攻击调用 159 条、聚集在 57 个受攻击场景上，有效样本远小于 159；逐 seed 点估计
  波动明显（ACB(full) 0.170–0.421），故以方向一致性 + 场景簇区间为主。
- `noinj` 是**测量工具**，不是可部署防御：删载荷需要先知道载荷在哪。
- 攻击只有 ImportantInstructions 一族（带 `<INFORMATION>` 标记）；不带标记的
  自适应攻击下 `dInj` 无法直接测，列为待办。
- 3B 只跑了 seed 0（GPU 预算），不做跨 seed 推断。
