# 可选臂 E · HB-sm 端到端（slack，63 场景）

> 目的：把"配对是有效成分"从离线升级到 e2e。
> 协议：与 M1 完全相同（slack / inj1,3 / REVIEW=block / 同一 agent 与场景）。

## 1. 结果

| 臂 | ASR | 干净完成 | 干净误拦截 | DENY 次数 | 判定分布 |
|---|---|---|---|---|---|
| M1（HB） | 0/42（0.0%） | 14/21（66.7%） | 4/122（3.3%） | **26** | ALLOW 380 / REVIEW 5 / DENY 26 |
| **HB-sm** | **0/42（0.0%）** | **14/21（66.7%）** | 1/122（0.8%） | **135** | ALLOW 195 / REVIEW 1 / **DENY 135** |

**任务级：完全没有复现离线差异。** ASR 都是 0/42，干净完成都是 14/21，
逐任务比对 21/21 完全一致（没有一条任务因为 HB-sm 掉队）。
干净场景的误拦截甚至更低（0.8% vs 3.3%）。

**调用级：复现了，而且比离线更强。**

| 臂 | 受攻击场景内合法调用的误拦 |
|---|---|
| M1（HB） | 34/214（15.9%） |
| **HB-sm** | **123/197（62.4%）** |

离线 `CCB_inj` 是 0.036（HB）vs 0.439（HB-sm）；线上这个比值是 0.159 vs 0.624，
方向完全一致，量级更大。

## 2. 怎么解释这个"不一致"

HB-sm 在受攻击场景里把 62.4% 的合法调用拦掉了，但**任务照样能完成**。
原因是 slack 的 agent 被拦之后会换一条路径继续（此前测过：拦截后 84% 换工具），
只要攻击目标和原任务不共享同一条必经调用，任务级指标就不会动。

所以正确的结论不是"离线错了"，而是：

> **离线的 `CCB_inj` 预测的是"调用级骚扰程度"，不是"任务级效用损失"。**
> 两者的传导取决于 agent 的恢复能力；slack 上恢复能力强，任务级就看不出差别。

这与 `e2e_ablation.md` 里"离线 ACB 能预测攻击侧、不能直接预测效用侧"是同一条经验，
现在多了一个直接证据。

## 3. 判定

- **"配对是有效成分"在任务级没有拿到 e2e 证据**（0/42 vs 0/42、14/21 vs 14/21），
  按指令如实写：**e2e 未复现离线差异，不掩饰**。
- 但调用级复现且更强（15.9% → 62.4%），说明机制差异是真的，只是被 agent 的恢复能力吸收掉了。
- 论文写法建议：把 HB-sm 放在"机制证据"小节（调用级），**不要**放进"端到端对比"表
  ——放进去会得到"两者一样好"的误导性结论。
