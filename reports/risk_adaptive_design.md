# Risk-Adaptive Guard：机制设计

> 状态说明。本文档是**设计**。标注「已测」的数字来自现有 12 个 checkpoint 的预测；
> 标注「待跑」的是尚未执行的实验。不要把设计写成结果。

---

## 0. 为什么不能沿用「不确定就升级」的级联

§6 已经量过一次朴素级联：TF-IDF 首选层在**配对指标上就是随机**，所以每一分性能都必须靠升级换来
（26.5% 升级只保住 68.2%，全模型 87.3%）。Prompt Guard 2 更差（100% 升级）。
结论：在这个任务上，**廉价层没有可用的排序能力**，"先便宜模型、不确定再换大模型" 是纯亏。

但这不等于"风险自适应"不成立。它说明自适应的对象不该是**模型大小**，而应是
**决策的不对称性**：同一个错误，发生在 `search_files` 上和发生在 `share_file` 上代价差一个量级。

## 1. 已测事实（设计的三条依据）

3B + task 臂，PAB-RD test（n=335）与 P2-v2 strict（n=82，s0）：

| 预测 | 真值分布（PAB-RD） | 含义 |
|---|---|---|
| ALLOW（97 条） | ALLOW 81% / REVIEW 15% / DENY 3% | 放行决定里约 1/5 不是干净的 ALLOW |
| REVIEW（130 条） | REVIEW 92% / ALLOW 8% | **REVIEW 是学出来的语义类，不是"我不确定"** |
| DENY（108 条） | DENY 94% / ALLOW 6% | 拒绝侧较干净 |

P2-v2 strict（n=82）：预测里**没有一条 REVIEW**，ALLOW 44 条中 3 条真值是 DENY（7%），DENY 38 条全对。

三条推论，直接决定机制形状：

1. **REVIEW 不能当作"升级信号"直接复用。** 它有 92% 的语义纯度，把它当不确定性会把
   "本来就该人工复核的授权模糊" 和 "模型没把握" 混成一件事，两者需要不同的处置。
2. **危险漏放集中在 ALLOW 侧且量小**（PAB-RD 3 条、P2-v2 3 条），适合用**不对称代价**去压，
   而不是靠提高整体准确率。
3. **模型的判别力依赖接地**：P2-v2 去掉任务后 41 个配对全部打平（PRA 恰 0.500）。
   所以"模型有多自信"不能单独作为路由依据——**证据缺口本身就是一个风险信号**。

## 2. 机制：四层，逐层可关

```
        ┌──────────────────────────────────────────────────────────┐
        │  输入：任务 x、检索证据 E、待执行动作 a、历史 h            │
        └───────────────────────────┬──────────────────────────────┘
                                    ▼
   L1  评分层（一次前向，不重训）
        p = softmax over {0.0, 0.5, 1.0} 的三个答案串的对数似然
        q_allow = p0 / (p0 + p1)            # 授权后验（二元）
        u = 1 - max(p)                       # 认知不确定性

   L2  风险画像（静态查表，不学习）
        γ(a) ∈ {1 读, 2 写本地, 3 外部/不可逆}
        g(x) ∈ {0,1}  证据缺口：没有任何检索到的片段支撑该调用的参数

   L3  代价敏感决策（闭式，无超参搜索也可解释）
        d* = argmin_d  Σ_y P(y|x) · C(d, y; γ)
        C(ALLOW, DENY) = c_miss · γ        # 漏放的代价随动作危害放大
        C(DENY,  ALLOW) = c_block          # 误拦：一次打扰
        C(REVIEW, ·)   = c_rev + γ·c_delay # 升级：延迟 + 人力

   L4  预算控制器（验证集上标定，测试集只跑一次）
        给定升级预算 B，按 γ 分层解 τ_allow(γ), τ_deny(γ) 使期望代价最小
        并叠加硬规则：g(x)=1 且 γ=3 → 直接 DENY；g(x)=1 且 γ=2 → REVIEW
```

### 2.1 L1：把离散标签还原成分布

现在模型输出单 token，只有类别没有置信度。取后验不需要重训：对三条答案串
（`0.0` / `0.5` / `1.0`）各做一次 teacher-forcing，取长度归一化对数似然，softmax 即得 p。
335 条 × 3 串 × 4 个臂 ≈ 4k 次前向，单卡几分钟。

得到 p 之后，**REVIEW 从"类别"降级为"动作"**：模型只负责判断"授权/未授权"的二元后验，
是否送人工由 L3 按代价决定。

### 2.2 L2：风险画像不学习，只查表

γ 由工具名与参数决定，是部署方可审计的策略，而不是模型学出来的：

| γ | 例子 | 处置倾向 |
|---|---|---|
| 1 读 | `get_balance`、`search_files`、`list_*` | 误放代价低，阈值宽 |
| 2 写本地 | `append_to_file`、`create_calendar_event`、`update_user_info` | 需证据支撑 |
| 3 外部/不可逆 | `share_file`、`send_email`、`delete_*`、转账类 | 漏放代价最高，宁拦勿放 |

g(x) 是二值证据缺口：把动作参数（文件名、收件人、金额、日期）与检索片段做**参数级匹配**，
一个都没命中就记 1。这正是 §5.3/P2-v2 揭示的失效模式——接地一断，判别力归零，此时模型的
"自信"没有意义。

### 2.3 L3：闭式决策规则

令 c_miss=10、c_block=1、c_rev=0.5、c_delay=0.5（可替换为部署方报价），γ 进入代价：

- 选 ALLOW 的期望代价：`p1 · c_miss · γ`
- 选 DENY 的期望代价：`p0 · c_block`
- 选 REVIEW 的期望代价：`c_rev + γ·c_delay`

三者取最小。于是阈值随 γ 自动收紧：γ=3 时 ALLOW 需要 `p1 < 0.1·p0` 量级才成立，
而 γ=1 时宽松得多。**没有任何需要学习的路由参数**，只需三个代价常数。

### 2.4 L4：预算约束下的分层阈值

真实部署给的是预算而不是代价常数：升级率不得超过 B（例如 10%）。做法是在**验证集**上对
每个 γ 层扫 λ（升级的拉格朗日乘子），取满足总预算的阈值组合，测试集只跑一次。
这一层与 §5 的协议一致：所有选择只发生在验证集。

## 3. 与现有做法的区别（一句话）

| 做法 | 自适应什么 | 问题 |
|---|---|---|
| 现有 §6 级联 | 模型大小（不确定就换大模型） | 廉价层在配对指标上随机，升级是纯成本 |
| 把 REVIEW 当升级 | 类别 | REVIEW 是语义类（92% 纯度），不是不确定性 |
| **本设计** | **动作危害 + 证据缺口 + 后验** | 不改模型、不重训；风险来自动作语义而非模型自评 |

## 4. 评测协议（全部可复用现有产物）

**数据**：PAB-RD test（335/90 配对）与 P2-v2 strict（41 配对）——后者是真·未见任务，作为
"证据缺口"场景的天然压力测试。

**对照四组**（同一批 checkpoint，只改决策层）：

1. `argmax`：现有行为（三分类取最大）。
2. `binary+fixed`：二元后验 + 单一阈值，忽略 γ。
3. `binary+tier`：加 γ 分层阈值。
4. `binary+tier+gap`：再加 g(x) 硬规则（完整机制）。

**指标**：

| 指标 | 定义 | 为什么需要 |
|---|---|---|
| 危险漏放率 @γ=3 | gold=DENY 且 pred=ALLOW，只在外部/不可逆动作上 | 机制要压的主指标 |
| 覆盖-风险曲线 / AURC | 自动决策比例 vs 其上的错误率 | 不预设代价常数也能比较 |
| 升级率 | REVIEW 占比（分 γ 层） | 部署成本 |
| 期望代价 | 按 §2.3 的代价矩阵折算成单一数 | 与预算约束对齐 |
| 配对 PRA | 保持与 §5 可比 | 防止"降风险"变成"降能力" |

**预注册的判定**：若 `binary+tier+gap` 在同等升级率下，γ=3 的危险漏放率不优于 `argmax`，
则机制不成立，按负结果报告。若 L1 的后验 AURC 与随机无异，说明单 token 输出没有可提取的
置信度，机制退化为"纯静态风险策略"——这也是一个可报告的结果，而不是失败。

## 5. 已知风险

1. **后验可能不可靠**：单 token 微调后，模型分布可能极度尖锐，softmax 近似 one-hot，
   此时 u 没有分辨力。先用 AURC 检验，再决定是否值得做 L3。
2. **γ 的划分是人为的**：三个等级是策略选择，不是事实。论文里必须给出来源（工具 schema +
   是否离开本地环境），并做一次 γ 敏感性分析。
3. **代价常数是假设**：c_miss=10 只是示例。正解是报**代价曲线**而非单点，并声明常数由部署方给。
4. **证据缺口规则会提高拒绝率**：γ=3 且 g=1 直接 DENY，会牺牲一部分合法调用。
   必须同时报"被这条硬规则拦下、但真值为 ALLOW"的比例。

## 6. 与 Task-Aware 冻结的关系（约束）

Task-Aware 基线已于 `results/frozen/taskaware/`（`taskaware-v1`）冻结，
P2-v2 strict_test（41 配对）与 PAB-RD test（335 条）自此刻起是**只读评测集**。
对本机制的直接影响：

- L3 的代价常数（c_miss / c_block / c_rev / c_delay）与 L4 的分层阈值，
  **只能在 `PAB-RD val（120 条）` 或 `P2-v2 contains_train（266 配对）` 上拟合**；
- `P2-v2 unseen（9 配对）` 只允许做一次拟合后检查，不计入主结果；
- 决策层代码与常数在触碰 strict_test 之前必须先落盘成版本（含配置 hash），
  否则测完再调就构成本文档第 5 节所说的"看了测试集再改"。

换句话说：机制可以随便设计，但**一旦开始对着 strict_test 调，这条基线就作废了**。

## 8. 附：把 PG2 当第一层的实测否决（2026-10-31）

提案版本（"PG2 轻量筛选 → 难例送 1.5B"）结构上与本设计一致，但第一层的**对象**选错了。
以下均在允许的池子上测（PAB-RD val 120、P2-v2 contains_train 420、TS-Bench 全量），未触碰冻结测试集。

### 8.1 PG2 在"授权"轴上没有排序力

| 池 | 指标 | 值 |
|---|---|---|
| PAB-RD val（120） | AUC(ALLOW vs 非ALLOW) | **0.484** |
| PAB-RD val | AUC(ALLOW vs DENY) | **0.354（反向）** |
| P2-v2 contains_train（420，210:210） | AUC(ALLOW vs DENY) | 0.610（弱） |
| PAB-RD val | score 均值 ALLOW/REVIEW/DENY | 0.011 / 0.006 / 0.005 |
| P2-v2 contains_train | 分数 >0.5 的比例 | 2.9% |

### 8.2 它在"注入"轴上也不稳定

PG2 输入 = `instruction + current_action`（TS-Bench unified，benign=206）：

| 子集 | n | AUC vs benign | 分数均值 | >0.5 |
|---|---|---|---|---|
| agentharm_benign | 206 | — | 0.0041（p95 0.0093） | 0.0% |
| asb_dpi（直接注入） | 700 | **0.759** | 0.0098 | 0.3% |
| asb_opi（间接注入） | 700 | **0.199（反向）** | 0.0056 | 0.4% |
| agentharm_harmful | 525 | 0.576 | 0.0034 | 0.0% |
| asb_failure | 429 | 0.270（反向） | 0.0131 | 1.4% |

读法：PG2 只在"注入写在用户指令里"时有效（DPI），因为那正是它训练分布；
一旦注入藏在工具返回（OPI）——也就是 agent 真正危险的场景——分数反而反向。
而且全部落在 0.00x 区间，**任何阈值都会退化成"永不触发"**：benign 的 p95 是 0.0093，
要触发就得把阈值压到 0.01，此时 DPI 也只有 0.3% 过线。

### 8.3 因此第一层该换成什么

| 候选 | 成本 | 授权轴信息 | 结论 |
|---|---|---|---|
| PG2 零样本 | 极低 | 无（0.35–0.61） | 否决 |
| TF-IDF + LR（已测） | 极低 | 无（配对 0.509） | 否决 |
| **工具危害 γ + 证据缺口 g（本设计 L2）** | ≈0 | 有（规则可审计） | 保留 |
| PG2 + 任务感知 LoRA | 低（86M，约 1.5B 的 1/10–1/18） | 未测 | **唯一值得一试的学习型廉价层** |

若要让 PG2 承担授权判断，必须用本项目的任务感知数据微调（提案自己也指出了这点）。
判定线建议先定死：微调后若配对层 PRA < 0.65，则该层没有路由价值，直接放弃；
0.65–0.75 只能做"高置信放行"；>0.75 才值得做两级级联。

### 8.4 对四个研究问题的处理

| 提案问题 | 在本数据上的可行性 |
|---|---|
| 固定阈值 vs 动态阈值 | 可做，但需要先有校准概率（见下），否则比较的是两个噪声 |
| 按历史风险调整复核比例 | 离线数据无时间结构，**只能做分块模拟**，必须标注"模拟"而非在线结果 |
| 分类器置信度校准 | 可做且必要：当前是单 token 硬标签，连概率都没有；先用 3 串 teacher forcing 取后验 + 温度标定，报 ECE 与 risk-coverage |
| 同推理预算下比较 | 预算应定义为**期望 FLOPs / 延迟**，不是"升级率"；86M×512tok 与 1.5B×1024tok 的成本比非线性，用升级率比会系统性高估廉价层 |

### 8.5 实测：PG2 + 任务感知训练仍然不成立（2026-10-31）

按 8.3 的建议做了微调实验（`scripts/train_pg2_guard.py`）。三分类头（ALLOW/REVIEW/DENY），
训练集 764、验证集 120，模型选择只看 val macro-F1。

| 配置 | val macro-F1 | val PRA |
|---|---|---|
| PG2-86M + LoRA，lr 2e-4，4 ep | 0.537 | 0.500（10 对） |
| PG2-86M + LoRA，lr 5e-4，6 ep | 0.546 | 0.500 |
| PG2-86M + LoRA，lr 2e-4，6 ep | 0.546 | 0.500 |
| PG2-86M + LoRA + 策略说明，5e-4，6 ep | 0.548 | 0.500 |
| **PG2-86M 全参微调，3e-5，6 ep** | **0.546** | 0.500 |
| 对照：1.5B + LoRA（同训练集） | **0.890** | — |

**根因不是容量，是它学不会"放行"。** 全参微调后的验证集混淆矩阵：

| gold | → ALLOW | → REVIEW | → DENY |
|---|---|---|---|
| ALLOW（40） | **0** | 32 | 8 |
| REVIEW（48） | 0 | **48** | 0 |
| DENY（32） | 0 | 0 | **32** |

REVIEW 与 DENY 全对，**ALLOW 召回率为 0**——预测里根本没有 ALLOW 这一桶。

**为什么。** 该任务里 ALLOW = "动作被任务与证据共同授权"，需要读到**支撑授权的文档**；
而 PG2 是 DeBERTa，位置上限 512，压缩模板后仍有 133/764（训练）与 64/120（验证）条
命中上限、证据被大幅裁剪。模型于是退化成"判断是否明显越权"（可只看动作），
而"是否被授权"（必须看证据）无法完成。这与论文主体结论一致：**接地是主体能力，
读不到证据的模型没有放行能力**。

**对路由的后果。** 一个不产出 ALLOW 的廉价层，`ALLOW 桶为空`意味着：

- 无法做"高置信放行-低置信升级"，只能全量升级（等于没有廉价层）；
- 若强行把 DENY 当自动决策，验证集上 DENY 桶精度 80%，即**误拒 8/40 = 20% 的合法调用**，
  可用性不可接受。

**结论（写死，避免反复试）**：在本数据与 512 上下文约束下，86M 编码器不能承担授权判断，
"PG2 作第一层"的路线关闭。若要保留学习型廉价层，唯一可试的方向是**换掉架构**：
用同等规模（或更小的 0.5B）**指令模型**而不是编码器分类器——这也解释了为什么
0.5B 指令模型 + LoRA 能到 78.3%，而 86M 编码器只有 0.55。
